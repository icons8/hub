= Sessions
hub session new <name> [--cwd DIR] [--mode M] [--icon E] ["<task…>"]
hub session new <name> [--cwd DIR] --agent --about "<what it does>" [--icon E]
: raise a claude session (or an agent — with --agent)
  Without --cwd — its own folder <state>/workspaces/<name>. Name: Latin letters, digits, hyphen, up to 40 chars.
  From a work session — a request to the hub: the core hands it the task, it opens it. Task in your repo — hub task run.
--cwd DIR  the session's folder
--mode M  Claude Code permission mode (default bypassPermissions)
--agent  a permanent agent: a professional with its own tools, not put to sleep until the owner dismisses it
--about "…"  what the agent does (shown in the list and to other sessions)
--icon E  the icon in the list (emoji)
@ owner, hub; session — by a request to the hub
$ hub session new maps --cwd /home/x/maps "fix the map tiles"
$ hub session new maps --agent --about "maps: tiles and geocoder" --icon 🗺
! an executor for your own task is not session new but hub task run (the result comes back to you)

hub session rename <name> <new>
: rename an asleep session; the old name stays an address
  The conversation, messages and schedule go with it.
@ owner, hub
$ hub session rename maps maps-tiles

hub session role <name> agent --about "…" [--icon E]
hub session role <name> worker [--for mN|qN]
: make a session an agent / dismiss an agent (worker)
  System sessions (hub-dev, agent-dev) cannot be dismissed, put to sleep or removed.
--about "…"  what the agent does
--icon E  the icon
--for mN|qN  the owner's word (to dismiss from the hub session)
@ owner, hub — dismissing: on the owner's word
$ hub session role maps agent --about "maps" --icon 🗺

hub session icon <name> <emoji>|--clear
: the session's own icon in the list; --clear removes it
--clear  remove the icon
@ owner, hub
$ hub session icon maps 🗺

hub session close <name>
: put to sleep: first it hands over (HANDOFF-DONE), then the process exits
  The conversation stays; hub session wake or a message wakes it.
@ owner, hub, raiser
$ hub session close maps

hub session compact [<name>]
: compact the session's conversation (/compact) when it is idle
  Without a name — yourself. A long session gets cheaper and does not lose the thread.
@ owner, hub, self
$ hub session compact maps

hub session effort [<name>] <low|medium|high|xhigh|max|default>
: the session's reasoning effort; default — from settings again
  An idle one is restarted with its conversation. Without a name — for yourself.
@ owner, hub, self
$ hub session effort maps high
! an executor's model and effort are set when it is raised: hub task run … --work risky

hub session model [<name>] <opus|sonnet|fable|haiku|claude-…|codex/<id>|default>
: the session's model; default — from settings again
  An idle one is restarted with its conversation. Without a name — for yourself.
  A hub on Codex: codex/<id> of its model list (the page's model menu); a bare listed id becomes codex/<id>.
@ owner, hub, self
$ hub session model maps sonnet

hub session cwd <name> <folder>
: the session's folder moved: same session and conversation — in the new folder
  Move the folder first, then run this command.
@ owner, hub
$ hub session cwd maps /home/x/maps-new

hub session parallel <name> <0..N|default>
: an own executor count for an agent or a direction
  0 — "solo", no executors; N — a mini-hub, up to N at once; default — the shared "Parallelism" from settings.
@ owner, hub, agent-dev
$ hub session parallel maps 3

hub session solo <name> on|off
: "solo" — no executors (same as parallel <name> 0); off — undo it
@ owner, hub, agent-dev
$ hub session solo maps on

hub session stop <executor…>
: stop an executor now: cut its turn, shut it down, put it to sleep
@ owner, hub, raiser
$ hub session stop maps-1
! the executor is still in the queue (not raised) — hub task cancel <name>

hub session interrupt <name…>
: cut the current turn of any session, like Esc; the session stays
@ owner, hub, raiser
$ hub session interrupt maps

hub session wake <name> [--about dN] ["<what to do>" | --file PATH | -]
: wake an asleep session; an executor that handed in — for rework (--about dN)
  With a text — wake it and give it work at once. Messages do not wake an executor that handed in — only this command.
  A mini-hub wakes its executor only for rework of its task, with a text: without --about — the one task it gave it.
--about dN  rework of task dN (right after the name; a mini-hub with several tasks of this executor names one)
--file PATH  the text from a file; `-` alone — from stdin (<<'EOF'), as for hub send
@ owner, hub, raiser
$ hub session wake maps-1 --about d12 "fix the review comments: …"
! a mini-hub without a text — the core refuses; with several handed-in tasks of the executor and no --about — too
! there is no --work here: the executor keeps its model; another kind of work — a new executor (hub task run)
! no free places — it joins the queue (hub task queue) and starts by itself

hub session reload <name>
: restart the process with the same conversation (MCP did not connect, it hung)
  An idle one at once; a busy one after its turn. An asleep one — hub session wake.
@ owner, hub, self
$ hub session reload maps

hub session revive <name>
: bring back a removed session with its conversation and tools
  An executor — also by whoever raised it (not a direction): the same conversation and folder, and the places of a new
  executor are needed.
@ owner, hub, raiser
$ hub session revive maps

hub session kit [<name>|--fleet] [--days 7|30|all] [--json]
: skills and MCP: loaded against opened
  What the page shows in "Skills and MCP", without the page. A session: per skill — how often it was opened (the model's
  Skill step, a /command, a read of its SKILL.md), in how many of the period's conversations, when last; what is loaded
  and never opened, with its tokens in the model's list; the MCP servers with their calls; the period's conversations
  and turns. Without a name — yourself. --fleet: the same per skill and server over the hub — in how many sessions it is
  loaded, how many opened it. The first call after an update reads the journal archives once (up to a minute).
--fleet  every session of the hub, executors too
--days D  the period: 7 (default), 30 or all
--json  the answer as the page gets it
@ anyone
$ hub session kit maps --days 30
$ hub session kit --fleet --json
! tokens are the model's skill list (Claude Code's get_context_usage): Codex does not say them — a dash

hub session remove <name…>
: remove an asleep or crashed session or an idle executor from the list
  The conversation stays on disk: claude --resume <id>.
@ owner, hub, raiser
$ hub session remove maps-1

= Messages and questions
hub send <to> [--now|--fyi] "<text>"
hub send <session> [--now] --about dN|mN "<text>"
hub send <session> [--now] --for mN [--card qN] "<the owner's words>"
hub send liaison --to <contact> [--thread T] "<what to pass on>"
: message to a session (address: name, sessionId, pid, socket); hub — to the hub
  A busy one gets it in its queue, after the turn. The text goes in quotes as one word; with $ or backticks in it — see --file.
--now  urgent: a busy one gets it mid-turn now, skipping the queue (hub, owner)
--fyi  for info: does not wake it, arrives with its next turn; only what does not change its next step
--about dN|mN  an addition to a task — reaches whoever is doing it
--for mN  (hub) the owner's words mN — to the session; its result goes to the owner where he wrote from
--card qN  (with --for) his words are the answer to its card qN
--to <contact>  to the liaison: pass on to a contact of another hub; to the owner's own hub (checked, bound to a person, no rule) the core sends it itself
--thread T  (with --to) the thread your words answer in, when you have several matters with that hub
--file PATH  the text from a file; the text `-` alone (or `--file -`) — from stdin (<<'EOF'). The shell runs backticks and eats $… in quotes, these do not
@ session, hub, owner — --now: hub, owner; --for: hub
$ hub send maps "tiles on stage are ready, check them"
$ hub send maps --about d12 "also: dark theme"
$ hub send maps --fyi "CI green on main"
$ hub send maps - <<'EOF'
! a message does not wake an executor that handed in: it goes to the raiser; a mini-hub's own executor with one task from it — a rework of that task, otherwise refused: hub session wake <name> --about dN "…"
! there is no --caption or --text: the text is one word in quotes after the name; --thread only with --to
! a review result, a request, a question — without --fyi: --fyi does not wake
! --fyi cannot be combined with --now, --for, --about, --card
! a script outside a session (systemd, cron) sets HUB_SCHEDULE_JOB=<name>: its text is then not the owner's word

hub answer <name> <answer> [<answer>…]
hub answer <name> --card qN <answer> [<answer>…] --why "<why · how to roll back>"
hub answer <name> --card qN --route rN --from "<person>" --msg <id> "<their words>"
: answer a session's AskUserQuestion (answers in question order)
  While the owner is away the hub answers a session's card for them — not their own decision (money, prod, people, the
  irreversible, a repo's gate, access): the session gets the hub's answer, not the owner's word; it goes into their
  return summary, and `hub decided undo <seq>` withdraws it.
--card qN  (hub, owner away) the card answered
--why "…"  (hub, owner away) why this answer and how to roll it back
--route rN  (the session of a deputy's channel) the route of the card: their words, with --from and --msg
--from "…"  (--route) the person who answered
--msg ID  (--route) the id of their message in the channel (each is taken once)
--file PATH  (--route) their words from a file; `-` alone — from stdin
@ owner, hub — --route: session, hub
$ hub answer maps "Yes"
$ hub answer maps --card q305 "tiles.toml" --why "short, like the files next to it · rename the file"

hub question withdraw <qN> ["why"]
hub question route <qN> <person> [--note "…"] [--own] | --owner
: withdraw a question to the owner (a duplicate, stale) — or send it to a deputy
  route — the owner is away with the deputies (hub away --deputies): the card to the deputy of its area. Every
  question of the card lies in that deputy's area and none in what they do not decide; never the owner's own decisions
  (money, prod, publishing, people, the irreversible, access) or the deputy's own request — except to a deputy who
  decides everything in their area (hub contacts deputy … --all): they act for the owner there, and all of it is theirs.
  To no deputy: the owner's personal data, their correspondence, a text in their name, what needs their own hands.
  Their answer comes to you on qN: their word, not the owner's. --owner — not theirs: the card waits for the owner,
  never another deputy.
--note "…"  (route) what the deputy should know besides the card
--own  (route) the card is about the deputy's own request (only one who decides everything takes it)
--owner  (route) back to the owner
@ self, hub — own card; hub — any
$ hub question withdraw q41 "already decided in m90"
$ hub question route q41 Masha --note "the folder has tiles.json already"

hub question show <qN>

@ hub, owner

hub decided "<what> · <why> · <rollback>"
hub decided --card qN "<what> · <deputy>, deputy · <rollback>"
hub decided list
hub decided undo <seq>
: (from a session) decided something reversible without the owner — into his summary
  list — the last recorded decisions (#seq, who, text; a withdrawn one marked). The core keeps the last 100; a hub
  updated to this version finds the earlier ones at its first start in the last 32 MB of the journal file, not in the
  journal archives.
  undo — withdraw a decision recorded by mistake: its author, the hub or the owner. It leaves the owner's summary and the
  direction's backlog, and whoever was told about it hears it is withdrawn; what was already done on it stays. A core
  started before this version refuses it until hub restart.
  --card qN — on a deputy's answer to your card qN (hub question route): the card closes, the owner's summary has it
  under "Decided by your deputies".
--card qN  your card at a deputy, answered: closed on their answer
--file PATH  the text from a file; `-` alone (or `--file -`) — from stdin (<<'EOF'): $ and backticks stay as typed
@ session
$ hub decided "tile cache 1 h · lowers load · rollback: TTL=0 in config"
$ hub decided undo 812
! flags like --q, --text are not needed here: everything goes as one text in quotes

--for 30m|2h|4h  term (default 4h)

hub run [--until 90m|6h|18:30] [--cwd DIR] "<command>"
hub run [--until T] [--cwd DIR] -
hub run list [--all]
hub run stop <id>
: up to 24 h outside the session, survives restarts; the result comes as a message
  For work that ends by itself and must outlive a hub restart or run past 2 h (an eval, a build, a wait for CI): the
  hub runs it in bash outside your session and sends you the exit code, the last lines and the log path. Not for a
  server (a dev server — run_in_background). Exports of your shell do not carry over: put them into the command.
  - — the command from stdin (a script with quotes). The log keeps the last 128 MB. Linux under systemd: all runs
  together get at most half of the memory. On macOS and Linux without systemd a process that detaches itself inside
  the command outlives the term. What the command leaves running when it exits is stopped: a run is the command and
  all it started. list — your runs and your executors'; stop — the whole run.
--until T  the term: 90m, 6h, 1h30m or 18:30 (the owner's time); default and at most 24 h
--cwd DIR  the folder (default: the current one)
--all  (list) every run of the hub — hub, owner
@ self — stop: self, raiser, hub, owner; list --all: hub, owner
$ hub run --until 4h "python3 evals/run.py --only after"
$ hub run stop run2061001
! setsid, nohup or a schedule job for long work — use hub run: they die with the hub's service or an executor's hand-in

hub contacts [find <who>]
hub contacts add "<name>" [--telegram @user:id] [--teams-chat ID] [--teams T] [--email E] [--alias A] [--note "…"] [--source "…"]

  take it off
--off  (deputy) no longer a deputy
--telegram @user:id  Telegram: @username and id
--teams-chat ID  Teams chat
--teams T  Teams (email or id)
--email E  email
--alias A  another name (can repeat)
--note "…"  note
--source "…"  where we know it from (owner, mN, chat)

= Tasks and executors
hub task new <to> "<what to do, why, when it is done>" [--work normal|risky] [--now]
hub task new <session> --for mN [--card qN] "<context>"
hub task new <session> --for-session S "<task>"
: a task for a session: the result comes back to you (with --for, to the owner)
--for mN  (hub) a task from the owner's message: his words go verbatim, the result goes to him
--card qN  (with --for) his words are the answer to this session's open card qN
--for-session S  at session S's request, the result goes to it
--work normal|risky  kind of work, in case the hub hands it to an executor
--model M  explicit executor model (owner from the terminal)
--effort E  explicit executor effort (owner from the terminal)
--now  urgent: to a busy session mid-turn, right now (hub, owner)
--file PATH  the text from a file; `-` alone (or `--file -`) — from stdin (<<'EOF'): $ and backticks stay as typed
@ session, hub, owner — --now: hub, owner; --for: hub
$ hub task new maps "add a dark tile theme; done = screenshots at 390 and 1440"
! you do not set a task for yourself: for later work, use hub task note or the direction's board

hub task run <name> "<task: what, why, when it is done>" --work normal|risky [--repo PATH [--here]] [--branch B] [--from-main] [--for mN|qN] [--tools id,id] [--board TASK-N] [--spec]
: raise an executor for a task: own copy, the result to you
  {model_rule}
  Own working copy (branch task/<name>) from the folder's current branch; your CLAUDE.md; handed in, it falls asleep by itself. No free slots: a queue.
  The name is the gist of the task in Latin letters: tiles-dark, geocoder-fix (up to 40 chars, not taken).
--work normal|risky  kind of work: a model pair from "Settings → Executors" (required from a session)
--model M  explicit model (owner from the terminal; overrides --work); on Codex codex/<id>, as in hub session model
--effort E  explicit effort (owner from the terminal)
--repo PATH  which repo (default: your folder)
--here  right in the existing copy PATH, without its own (where nobody works)
--branch B  a copy on the existing branch B
--from-main  a branch from the repo's main branch (from origin, if the local one is behind)
--for mN|qN  the owner's word: even above 85% of the weekly limit
--tools id,id  starts with these tools already
--board TASK-N  the direction's board card the work is for
--spec  spec mode (only with specs on — a person's /spec on): it writes only the spec (specs/<dN>/spec.md) until the owner accepts it
--spec-dir NAME  the spec's folder in specs/ instead of dN: a new spec of a topic next to its earlier one
--file PATH  the task text from a file; `-` alone (or `--file -`) — from stdin (<<'EOF'): $ and backticks stay as typed
@ session, hub, owner
$ hub task run tiles-dark "dark tile theme; done = screenshots 390/1440 and green tests" --work normal
$ hub task run geocoder-fix "fix the geocoder on prod data" --work risky --repo /home/x/maps --from-main
! without --work from a session: refused with the rule
! --here on your own working folder: refused; only in an existing free copy
! name taken: pick another name (or hub session wake <name> for follow-up work)
! a copy from main — --from-main; an existing branch — --branch B; there is no --branch-from

= Schedule
hub schedule add [--session S] (--at "YYYY-MM-DD HH:MM" | --every 30m|2h|1d | --cron "m h dom mon dow") --prompt "…" [--until YYYY-MM-DD] [--id ID] [--check "<command>"]

: set a job: a timed session turn or a monitor command
  Time is in the owner's time zone. A repeating job lasts up to 14 days (max 30); extend it — hub schedule extend.
  --check: the clock runs the command in the session's folder before the turn (2 min by default, --check-timeout S sets
  the limit); code 0 — nothing new,
  don't wake; 3 — wake, its output goes in the text; another code — wake with the check error.
  A polling job (comments, a deploy, mail) — with --check whenever a command can tell what is new (--every 1m works).
  --command: a script on a schedule, no end date; writes to the owner itself (hub notify); output: logs/schedule/ID.log.
  --command and --check run in the OS shell: /bin/sh on Linux and macOS, cmd.exe on Windows (not bash: no sh, grep,
  dirname, $VAR); complex things go in a script (full path: --command runs from home, --check from the session's folder).
--session S  whose turn (default: yourself); with --command — whose command
--at "YYYY-MM-DD HH:MM"  once
--every 30m|2h|1d  repeat
--cron "m h dom mon dow"  by cron
--prompt "…"  the text of the session's turn
--command "…"  a shell command (monitor)
--until YYYY-MM-DD  until which day
--id ID  your own job name (required with --command)
--check "…"  a pre-check without a turn (only with --prompt)
--check-timeout S  seconds the check may run: 1–900, default 120 (needs --check)
@ session, hub, owner — to change: setter, recipient, hub, owner

! there is no --text: the text of the turn — --prompt "…", a shell command — --command "…"

hub secret list

: (owner) clone into the app and back; src, apply: own core
  The app's installer runs these: find — the clone this state folder's hub runs from (code 3 — none); move — waits
  for busy sessions, stops it, saves the service files and hub.json, a backup branch of the own edits of the core in
  the clone, the app's programs in hub.json; --done — the app's hub came up. stay — "Stay on the clone". undo — the
  service back on the clone, hub.json from the copy (within 14 days of the move; --failed — the installer's own).
--json  for the installer: the clone and the dialog's words
--app <folder>  the app's folder (its programs)
--done  the app's hub came up: the move is done
--failed  the installer's undo of a move that did not come up
  src — the core's working copy of a hub from the one-line install, <state>/own/core: git, the branch local (own
  edits) over release (the commit of the release the hub runs); a clone of the release's source repository when this
  machine has access (its tests, origin for a PR), else the release's own files without tests. Again after an update:
  release moves to the new one, local is never touched (merge on request: git merge release). The hub keeps running
  its built release. apply — builds the hub's code of local (committed, over release) by the release's own factory:
  <release>+local.<sha>, left for the person's restart ("Restart" on the page and in Telegram) under the update's
  watchdog; a build that does not come up goes back to the clean release. "Return the released" takes it off; a new
  release installs clean, the edits stay on local.
--repo URL  src: clone this repository instead of the release's source
--json  src: the copy as JSON
